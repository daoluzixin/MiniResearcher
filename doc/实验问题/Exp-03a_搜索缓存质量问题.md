# Exp-03a：搜索缓存质量极差导致训练无效

**日期**: 2025-05-26
**实验**: Exp-3a baseline（无 PBRS）
**服务器**: AutoDL 单卡 A100-80G

---

## 现象

训练 73 步，reward 始终在 -0.65 ~ -0.88 震荡，无任何改善趋势。search_depth 停留在 1.0-1.6，模型完全没学会有效搜索。info_gain ≈ 0。

## 根因

### 缓存来源问题

初始服务器上的缓存文件有 12,636 条（49MB），看似充足。但经分析发现：

- **75% 是垃圾数据**：英文 query 对应中文无关搜索结果（可能是之前 DuckDuckGo/百度混合抓取的残留）
- 有效缓存实际只有约 3,000 条，且覆盖的 query 不匹配模型实际生成的 query

### 匹配率分析

从训练日志提取模型实际产生的 2,296 个不同 query，检查缓存命中情况：

| 匹配方式 | 命中率 | 说明 |
|----------|--------|------|
| 精确匹配 | **0%** | 没有一个 query 完全命中 |
| Fuzzy 匹配（Jaccard ≥ 0.2） | **28%** | 匹配到的内容大多也是无关信息 |
| 有效搜索结果 | **~5%** | 能实际帮助回答问题的结果 |

### 连锁影响

搜索结果无关 → F1 reward ≈ 0 → 无正向梯度 → 模型学到"搜索没用" → search depth 不增长

## 解决方案

### 短期（本次实验）

1. **上传本地高质量缓存**（540 条 → 后补充至 2,231 条）
2. 高质量缓存标准：
   - 针对模型实际 query 搜索（从训练日志提取 query）
   - 确保搜索结果与 ground truth 有 token overlap
   - 每个 query 至少 3 条有效搜索结果

### 长期

1. **扩大缓存覆盖**：针对训练数据的所有可能 query 变体预搜索
2. **在线搜索 fallback**：缓存未命中时走真实搜索引擎（需要网络环境）
3. **缓存质量验证脚本**：上传前自动检查缓存的 query-result 相关性

## 高质量缓存的要求

1. **覆盖率**：覆盖模型训练时产生的 query（至少 80% 命中率）
2. **相关性**：搜索结果与 ground truth 的 token overlap > 0.1
3. **多样性**：每个 query 提供 3-5 条不同来源的结果
4. **去噪**：去除导航栏、广告、无关 snippet

## 教训

- 缓存条目数量不代表质量，必须验证"模型实际 query → 缓存结果 → 对回答有帮助"的完整链路
- 离线训练的搜索环境质量是实验成功的前置条件
- 建议每次训练前运行缓存覆盖率检测脚本
